# コンディション予報

睡眠記録から当日の「注意・反応％」を計算し、行動の直前に送る通知の計画を返す静的ページです。
計算はすべてページが行い、AIエージェント（Muse）は URL を開いて結果を読み、通知を予約するだけです。

- 公開URL：`https://aaaxkan-wq.github.io/-/forecast/`（`main` に反映されると公開されます）
- 成果物は `index.html` の1ファイルだけ。CSS と JavaScript を内包し、外部への通信・保存は一切しません
- ビルド不要。`index.html` を編集してそのまま公開できます
- リポジトリとテストに、実際の睡眠記録は含めていません（サンプルもテストも合成データ）

## 使い方

睡眠記録を URL の `#` 以降に付けて開きます。`#` 以降はサーバーに送られないため、睡眠記録はホスティング側のログに残りません。

```
https://aaaxkan-wq.github.io/-/forecast/#s=2026-11-08T23:10/2026-11-09T06:45,2026-11-09T23:40/2026-11-10T06:50&now=2026-11-10T07:10&gym=18:30
```

（上の例は区間を2日分に省略しています。実際には7日分以上が必要です）

| キー | 必須 | 形式 | 既定値 | 意味 |
|---|---|---|---|---|
| `s` | 必須 | `開始/終了` をカンマ区切り。各時刻は `YYYY-MM-DDTHH:MM`。末尾に `Z` や `+09:00` を付けてもよい | なし | 睡眠中の記録。ステージごとの細切れでもよい。直近14日分を推奨、最低7日分 |
| `now` | 推奨 | `s` と同じ書式 | 時計の絶対時刻を `tz` で換算した値 | 現在時刻 |
| `tz` | 任意 | `+HH:MM` | `+09:00` | 利用者の現地時刻の時差 |
| `need` | 任意 | 分 | `450` | 必要睡眠時間 |
| `bed` | 任意 | `HH:MM` | `23:00` | 就寝目標 |
| `wake` | 任意 | `HH:MM` | 直近7日の起床時刻の中央値 | 翌朝の起床予定 |
| `act` | 任意 | `HH:MM-HH:MM` | `08:00-17:00` | 日中の活動時間帯 |
| `cafmg` | 任意 | mg | `107` | カフェイン1回分の想定量 |
| `whatif` | 任意 | `HH:MM` をカンマ区切り | `bed`、`bed`+60分、`bed`+90分 | 比較する就寝時刻 |
| `gym` | 任意 | `HH:MM` | なし | 運動の予定時刻 |
| `win` | 任意 | `HH:MM-HH:MM` | なし | 集中に向く時間帯を探す範囲 |
| `shift` | 任意 | 分（正負） | `0` | 推定した体内時計の位置への追加補正 |
| `none` | 任意 | `YYYY-MM-DD` をカンマ区切り | なし | 「寝ていない」と確認した日。その日の朝までの晩を、記録の欠けではなく睡眠なしとして扱う |
| `max` | 任意 | 件数 | `5` | 1日の通知上限 |

- 末尾に `Z` や `+09:00` が付いた時刻は `tz` の時刻に換算し、付いていない時刻は `tz` の現地時刻として扱います。ブラウザのタイムゾーン設定は使いません。
- 同じキーを `?` 以降（クエリ文字列）で渡しても受け付けます。両方にあるときは `#` 側を優先します。
- パラメータなしで開くとサンプルデータで表示します（`demo` が `true`、`notifications` は空）。

結果は `<pre id="muse-result">` に JSON で出力します。キー名と順序は固定です。`status` は次の3つです。

| `status` | 意味 | `notifications` |
|---|---|---|
| `ok` | 計算できた | 通知計画（`at` はオフセット付きの日時、`time` は表示用の `HH:MM`） |
| `need_last_night` | 昨夜の睡眠記録がない。`error` は「昨夜の睡眠記録がありません」 | 空 |
| `error` | 入力が不正。理由は `error` | 空 |

仕様書にない項目として、次の4つを追加しています。

| キー | 中身 |
|---|---|
| `now_state`（`attention_now` の直後） | 今の状態を、ことばで言い換えたもの。`{ "level": "fair", "label": "やや低下", "like": "よく眠った人の夜10時ごろ（起きてから15時間）", "vs_usual": 0, "text": "今の注意・反応は92%（やや低下）で、…" }`。`level` は `good`・`fair`・`low`・`danger`、`vs_usual` はいつもの今ごろとの差（比べられる日が3日未満なら `null`） |
| `day_plan`（`valley` の直後） | 今日の過ごし方。`{ "items": [{ "start": "08:40", "end": "10:10", "kind": "focus", "text": "今日いちばん冴える。考える作業や大事な判断に" }, …], "text": "08:40〜10:10：…。" }`。`kind` は `wake`・`focus`・`dip`・`second`・`bath`・`bed`。終わった時間帯は載せない |
| `bedtime_advice`（`bedtime_compare` の直後） | 今夜のおすすめ就寝時刻。`{ "by": "23:15", "wake": "06:45", "sleep_min": 450, "next_day_avg": 93, "usual_avg": 93, "text": "明日06:45に起きるなら、遅くとも23:15までに寝てください（7時間30分眠れて、明日の日中は平均93%の見込み）。" }`。起床予定まで1時間を切ると `null` |
| `evening`（`bedtime_advice` の直後） | 夜の注意・反応の下がり方。`{ "top": "19:23", "limit": "00:52", "limit_reached": false, "text": "注意・反応は19:23ごろが夜のピークで、…" }`。`top` は夜のピーク、`limit` は起き続けたときに77%を下回る時刻（起床予定までに下回らなければ `null`）、`limit_reached` はすでに下回っているか |

## Muse への指示文

次の文面を Muse に渡し、手順として覚えさせます。仕様書7章の文面に公開URLを入れ、次のところを変えています。

- ★の1行：3時間未満しか眠れなかった日に、同じ質問が繰り返されるのを防ぐため（貼り付けるときは★を消してかまいません）
- 「質問されたとき」の「今の脳機能は？」「今日はどう過ごせばいい？」「今夜は何時に寝ればいい？」「何時まで起きていて大丈夫？」：追加した機能に答えるため

```
「コンディション予報ページ」を使って、睡眠にもとづく通知を毎日行ってください。数値の計算はすべてページが行います。自分では計算しないでください。

■ 毎日の実行
1. 毎朝6:30から11:00まで、30分ごとにApple Healthの睡眠記録だけを確認する。
2. 今朝までに終わった、合計3時間以上の睡眠記録が見つかったら、その回で「朝の手順」を行い、その日の確認を終える。
3. 11:00の回でも見つからなければ、そのまま「朝の手順」を行う。

■ 朝の手順
1. Apple Healthから直近14日間の睡眠記録を取得する。使うのは「睡眠中」の記録（コア・深い・レム・ステージ不明）だけで、「ベッドにいた時間」と「覚醒」は使わない。間が10分未満で続いている記録は、1つの区間にまとめてから書く。まとめられない場合は、そのまま並べてもよい。
2. 次の形式でURLを作る。
   https://aaaxkan-wq.github.io/-/forecast/#s=<開始/終了をカンマ区切り>&now=<現在時刻>
   時刻の書式は YYYY-MM-DDTHH:MM。Apple Healthの時刻がUTCやオフセット付きなら、末尾の Z や +09:00 を付けたまま書く。
   運動の予定がある日は &gym=HH:MM を付ける。
   補正の値（shift）が決まっていれば &shift=<分> を付ける。
3. ブラウザでURLを開き、id が muse-result の要素にあるJSONを読む。
4. status に応じて次のとおりにする。
   - ok：demo が false であることを確かめて、5へ進む。
   - need_last_night：「昨夜の睡眠記録が見つかりません。寝た時刻と起きた時刻を教えてください」と私に聞く。答えの時刻を s に加えて、2からやり直す。「寝ていない」と答えたら、&none=<今日の日付 YYYY-MM-DD> を付けてやり直す。
     ★時刻を加えても need_last_night が返るとき（3時間未満しか眠れなかった日）は、聞き直さずに &none=<今日の日付 YYYY-MM-DD> も付けてやり直す。
   - error：通知は予約せず、error の内容を私に伝えて終える。
5. notifications の各項目について、at の日時に text の文面で通知を予約する。文面は書き換えない。
6. at が現在時刻以前の項目は、すぐに送る。
7. imputed_nights に日付があれば、「記録がなかった日（日付）は、普段の睡眠で補って計算しました」と1行伝える。

■ 質問されたとき
最新の睡眠記録と現在時刻でURLを作り、次のパラメータを付けて開く。
- 「今の脳機能は？」「今の調子は？」：now_state の text を答える。
- 「今日はどう過ごせばいい？」：day_plan の text を答える。
- 「今夜は何時に寝ればいい？」：bedtime_advice の text を答える。
- 「あと1時間起きていたら？」「○時に寝たらどうなる？」：&whatif=HH:MM,HH:MM を付け、bedtime_compare を答える。
- 「何時まで起きていて大丈夫？」「夜はいつから頭が働かなくなる？」：evening の text を答える。
- 「今カフェインを摂っていい？」：caffeine_cutoff と現在時刻を比べて答える。量が分かるときは &cafmg=<mg> を付ける。
- 「何時に作業や勉強をするのが良い？」：&win=HH:MM-HH:MM を付け、focus_window を答える。

■ 補正
- 「谷の通知が早い」と言われたら、ずれの分数を正の値で shift にする。「遅い」と言われたら負の値にする。以後のURLにも同じ値を付ける。

■ 守ること
- ページが返した数値と文面をそのまま使う。推測で補わない。
- ページが開けない、またはJSONが読めないときは、通知を予約せず、そのことを私に伝える。
- 結果は目安として伝える。診断や治療の助言にはしない。
- ページが返した件数を超えて通知しない。
```

以前の指示文のままでも動きます（通知の `time` と `text` は従来どおり返します）。ただし、記録の欠けを聞き返す手順と `at` での予約は、新しい指示文でだけ働きます。

## 仕様書にない、追加した機能

利用者の依頼で、次の4つを追加しています。通知の件数は増やさず、既存の通知に文を添えます。

- 今の状態を、数値だけでなくことばで伝える（`now_state`）
- 今日の過ごし方を時間帯ごとに伝える（`day_plan`）
- いつ寝た方がいいか（`bedtime_advice`）
- 夜、いつ頭が働かなくなるか（`evening`）

### 今の状態の言い換え（`now_state`）

数値を、よく眠った人（23:00〜07:00 を14日）が 07:00 に起きて、そのまま起き続けた場合の値と比べて言い換えます。
すべて4.1節の式による試算です。

| よく眠った人 | 値 | 段階 |
|---|---|---|
| 日中（08:00〜17:00） | 93〜97% | 93%（日中の最低）以上は「良好」 |
| 夜11時ごろ（起きてから16時間） | 87% | 87%以上は「やや低下」 |
| 深夜1時ごろ（起きてから18時間） | 77% | 77%以上は「低下」。77%は「18.5時間起き続けた状態」「血中アルコール濃度0.05%」と同水準とされる値（4.1節）。17〜19時間起き続けると、一部の検査で血中アルコール濃度0.05%と同等以下になったという研究（Williamson & Feyer 2000）とも合います |
| 徹夜した明け方5時ごろ | 67% | 77%未満は「大きく低下」 |

- `like`：今の値が、よく眠った人の何時ごろと同じか（夜のピークの後に初めてその値を下回る時刻を、30分単位に丸める）。日中の最低以上なら「よく眠った日の日中」、徹夜の明け方の最低より下なら「徹夜して明け方を迎えたとき以下」
- `vs_usual`：直前7日の同じ時刻（起きていた日だけ）の中央値との差
- `text`：段階・言い換え・いつもとの差に、今の時間帯（起きてすぐ・冴える時間帯の前／中・下がり気味・もう一度上がる・夜の下がり）と、段階ごとの一言を添えます。一言は「睡眠不足で落ちるのは、考える作業より注意を保ち続ける作業」という研究（Lim & Dinges 2010）にもとづきます
- 画面：大きな数値の横に段階を、その下に言い換えと、よく眠った人の値を並べた「はしご」を出します

### 今日の過ごし方（`day_plan`）

| 時間帯 | 決め方 | 文 |
|---|---|---|
| 起きてすぐ | 起床から30分（仕様書の仮眠の文面と同じ） | 起きてすぐの鈍さが残る。大事な判断は避ける |
| 冴える | ピーク時間帯（4.1節） | 今日いちばん冴える。考える作業や大事な判断に |
| 下がり気味 | 谷を含み、注意・反応が今日の日中平均を下回り続ける時間帯（5分単位、30分未満なら出さない） | 下がり気味（いちばん低いのは{谷}ごろ）。単純作業や休憩に。カフェインは{締切}まで |
| もう一度上がる | 下がり気味の後から、入浴（早く寝る日は就寝の90分前）までで、90分の平均が最大の区間。日中平均より高いときだけ | もう一度上がる。勉強や細かい作業に |
| 入浴 | 就寝目標の90分前（4.6節）。おすすめ就寝まで1時間を切る日は、就寝の行にまとめる | 入浴（40〜42.5℃で10分以上） |
| 就寝 | おすすめ就寝時刻 | おすすめの就寝時刻（遅くともこの時刻までに） |

- 冴える時間帯ともう一度上がる時間帯の平均が77%に届かない日は、「今日の中ではいちばんまし。大事な作業はできるだけここに」「少し持ち直す。急ぎの作業はここに」にします
- 通知：morning の日中平均に言い換えを添え（「日中平均93%で、よく眠った日の日中と同じくらいです」）、もう一度上がる時間帯を1文加えます。valley には「{下がり気味の終わり}ごろから持ち直します」を加えます

### 今夜のおすすめ就寝時刻（`bedtime_advice`）

次の2つのうち早いほうを、5分刻みで切り下げて出します。すでに過ぎていれば「すぐに」と伝えます。

1. 翌朝の起床予定（`wake`、既定は直近7日の起床時刻の中央値）から、必要睡眠時間（`need`）をさかのぼった時刻
2. 明日の日中平均が「普段」（直前7日の日中平均の中央値）を0.5ポイント以上は下回らない、いちばん遅い時刻（4.1節の式で、就寝時刻を変えて試算する）

2は「就寝目標の3時間前」から「起床予定の3時間前」までの範囲で探します。この範囲のどこで寝ても普段に届かない日（徹夜の翌日など）は、範囲の始まり（就寝目標の3時間前）を出します。

| 状況（試算） | おすすめ | 決め手 |
|---|---|---|
| 23:00〜06:30 の睡眠が続く | 23:00（7時間30分） | 1（必要睡眠時間） |
| 23:00〜06:30 の後、1晩だけ 01:30〜06:30 | 21:55（8時間35分） | 2（明日を普段どおりに戻す） |
| 00:30〜06:30 の睡眠が続く（不足が続いている） | 23:00（7時間30分） | 1（普段の水準が低いため、2より早い） |
| 寝ていない日（`none`） | 20:00（10時間30分） | 2の範囲の始まり |

- 文：night の通知に「明日{起床}に起きるなら、遅くとも{時刻}までに寝てください（{長さ}眠れて、明日の日中は平均{値}%の見込み）。」を添えます（入浴の文の直後）。通知の時刻にすでに過ぎていれば「すぐに寝てください（今寝ると{長さ}眠れます）。」にします。

### 夜のピークと、77%を下回る時刻（`evening`）

- `top`：午後の谷から翌03:00までで、注意・反応が最も高い時刻（起き続けた場合）。これを過ぎると下がり続けます
- `limit`：起き続けた場合に、注意・反応が77%を下回る最初の時刻（1分刻み、起床予定まで探す）。77%は「18.5時間起き続けた状態」「血中アルコール濃度0.05%」と同水準とされる値です（4.1節の目安）
- 文：
  - 就寝目標より後に下回るとき：night の通知に「{時刻}を過ぎても起きていると、注意・反応が18.5時間起き続けたのと同じ水準（77%）を下回ります。」
  - 就寝目標より前に下回るとき（寝不足の日）：morning と night の通知に「{時刻}ごろから、…を下回る見込みです。それ以降は車の運転や危険を伴う作業を控えてください。」
  - すでに下回っているとき：「注意・反応はすでに…を下回っています。車の運転や危険を伴う作業は控えてください。」
- 画面：グラフに77%の線を引きます

このモデルが出すのは注意・反応の速さで、「眠い」という感覚そのものではありません。そのため「眠くなる時刻」ではなく「頭の働きが落ちる時刻」として伝えます。

## 仕様書に書かれていない部分の扱い

仕様書（コンディション予報ページ 仕様書）どおりに実装したうえで、定めのない部分は次のように決めています。

### 記録の欠け・睡眠なし

| 場面 | 扱い |
|---|---|
| 昨夜の欠けを判定する時刻 | `now` が「普段の睡眠の中央の時刻」（普段が 23:00〜06:30 なら 02:45）を過ぎてから判定する。それより前は、まだ寝る前とみなして計算する（夜更かし中の質問で「昨夜の記録がない」と聞き返さないため） |
| 「寝ていない」と確認した日（`none`） | 普段の起床時刻から1日が始まるものとして、その日の通知計画を作る。`wake_time` は `null`。その晩に3時間未満の記録があれば、そのまま計算に使う |
| 欠けた晩に補う区間 | 欠けていない晩それぞれについて「その晩にいちばん長く重なる睡眠」の始まりと終わりを取り、その中央値を使う。その晩に短い記録が残っていれば、補った区間と合わせる |
| `imputed_nights` の日付 | 補った晩が明けた朝の日付（`none` と同じ数え方） |
| 睡眠記録が7日分に足りない | エラー（睡眠負債と起床予定の中央値が計算できないため。補った晩も1日分に数える） |
| `now` より後に終わる睡眠記録がある | エラー（`now` や `tz` の取り違えで誤った値を出さないため） |

### 起床時刻・集計

| 場面 | 扱い |
|---|---|
| 10分以上の途中覚醒で分かれ、どの区間も3時間未満 | 起床時刻の判定に限り、間隔60分以内の区間はひと続きの睡眠として数える（モデルの計算には、10分未満だけをつないだ区間を使う） |
| 昨夜の記録は3時間以上あるが、ひと続きの睡眠が無い | 昨夜の最後の記録の終わりを起床時刻にする |
| 起床が活動時間帯の開始より遅い | ピーク・谷・日中平均は、活動時間帯のうち起床から就寝目標までの部分で集計する |
| 睡眠負債の「直近7日」と「昨夜」 | 正午区切りで、当日の朝までの7晩。`last_night_sleep_min` はその最後の晩の睡眠合計 |
| 2分などの短い中断 | モデルの計算ではつなぐ。睡眠合計（睡眠負債・寝不足の判定など）には含めない |
| 「直前7日の日中平均」 | 各日の活動時間帯のうち、起きていた分の平均。履歴がその日まで届かない日は除く |
| 見落とし予告のしきい値 | 表示する値（`drop` は小数1桁、`avg7_sleep_min` は分に丸めた値）で判定する |
| 探す刻み | 谷は1分刻み。ピーク時間帯と集中に向く時間帯は5分刻み（平均は1分刻みの値から計算） |
| `clock_peak` | 推定した位置そのもの（`shift` は含めない）。分未満は切り捨て |

### そのほか

| 場面 | 扱い |
|---|---|
| `win` が `now` より前から始まる | `now` より前の区間は選ばない |
| `whatif` の時刻がすでに過ぎている | その時刻は比較に入れない |
| `whatif` が3件でない | night の文面は、件数に合わせて「〜なら〜%」を並べる |
| 時刻の書式 | 秒付き（`07:10:30`）や `+0900` の形も受け付ける。秒は切り捨てる |
| サンプル表示 | 固定の合成データと固定の現在時刻（2026-11-11 07:10）で計算する。画面には通知の見本を出すが、結果ブロックの `notifications` は空 |
| 同じタブで `#` 以降だけが変わった | 計算し直して描き直す |

## テスト

```
node --test forecast/test/*.test.js
```

- `forecast.test.js`：計算部の単体テスト。`index.html` から計算部（`<script id="core">`）を取り出し、Node だけで実行します。仕様書8章の基準値をすべて含みます。
- `browser.test.js`：実際のブラウザでの確認（幅360pxで横スクロールなし、外部通信なし、ライト／ダーク、`#` の変更で再計算、ブラウザのタイムゾーン設定に左右されないこと）。Playwright が無い環境では自動的に省略されます。

## 構成

```
forecast/
  index.html              成果物（これだけを公開すれば動く）
    <script id="core">    計算部。純粋関数だけ（DOM・時計・保存領域を使わない）
    <script id="ui">      画面部。計算結果を描画するだけ
  test/                   テスト（合成データ）
```
