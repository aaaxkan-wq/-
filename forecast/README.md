# コンディション予報

睡眠記録から当日の「注意・反応％」を計算し、行動の直前に送る通知の計画を返す静的ページです。
計算はすべてページが行い、AIエージェント（Muse）は URL を開いて結果を読み、通知を予約するだけです。

- 公開URL：`https://aaaxkan-wq.github.io/-/forecast/`（`main` に反映されると公開されます）
- 成果物は `index.html` の1ファイルだけ。CSS と JavaScript を内包し、外部への通信・保存は一切しません
- ビルド不要。`index.html` を編集してそのまま公開できます

## 使い方

睡眠記録を URL の `#` 以降に付けて開きます。`#` 以降はサーバーに送られないため、睡眠記録はホスティング側のログに残りません。

```
https://aaaxkan-wq.github.io/-/forecast/#s=2026-11-08T23:10/2026-11-09T06:45,2026-11-09T23:40/2026-11-10T06:50&now=2026-11-10T07:10&gym=18:30
```

（上の例は区間を2日分に省略しています。実際には7日分以上が必要です）

| キー | 必須 | 形式 | 既定値 | 意味 |
|---|---|---|---|---|
| `s` | 必須 | `開始/終了` をカンマ区切り。各時刻は `YYYY-MM-DDTHH:MM` | なし | 睡眠区間（仮眠を含む）。直近14日分を推奨、最低7日分 |
| `now` | 推奨 | `YYYY-MM-DDTHH:MM` | ブラウザの現在時刻 | 現在の現地時刻 |
| `need` | 任意 | 分 | `450` | 必要睡眠時間 |
| `bed` | 任意 | `HH:MM` | `23:00` | 就寝目標 |
| `wake` | 任意 | `HH:MM` | 直近7日の起床時刻の中央値 | 翌朝の起床予定 |
| `act` | 任意 | `HH:MM-HH:MM` | `08:00-17:00` | 日中の活動時間帯 |
| `cafmg` | 任意 | mg | `107` | カフェイン1回分の想定量 |
| `whatif` | 任意 | `HH:MM` をカンマ区切り | `bed`、`bed`+60分、`bed`+90分 | 比較する就寝時刻 |
| `gym` | 任意 | `HH:MM` | なし | 運動の予定時刻 |
| `win` | 任意 | `HH:MM-HH:MM` | なし | 集中に向く時間帯を探す範囲 |
| `shift` | 任意 | 分（正負） | `0` | 体内時計の位相補正 |
| `max` | 任意 | 件数 | `5` | 1日の通知上限 |

- 同じキーを `?` 以降（クエリ文字列）で渡しても受け付けます。両方にあるときは `#` 側を優先します。
- パラメータなしで開くとサンプルデータで表示します（`demo` が `true`、`notifications` は空）。
- 入力が不正なときは計算せず、理由を `error` に入れて返します（`status` が `error`、`notifications` は空）。

結果は `<pre id="muse-result">` に JSON で出力します。キー名と順序は固定です。

## Muse への指示文

次の文面を Muse に渡し、手順として覚えさせます。

```
「コンディション予報ページ」を使って、睡眠にもとづく通知を行ってください。数値の計算はすべてページが行います。自分では計算しないでください。

■ 毎朝の手順（起床後に1回）
1. Apple Healthから、直近14日間の睡眠記録を取得する。仮眠も含め、各区間の入眠時刻と覚醒時刻を使う。
2. 次の形式でURLを作る。時刻はすべて現地時刻とする。
   https://aaaxkan-wq.github.io/-/forecast/#s=<開始/終了をカンマ区切り>&now=<現在時刻>
   時刻の書式は YYYY-MM-DDTHH:MM。
   運動の予定がある日は、末尾に &gym=HH:MM を付ける。
3. ブラウザでそのURLを開き、id が muse-result の要素にあるJSONを読む。
4. status が ok で、demo が false であることを確かめる。違う場合は通知を予約せず、error の内容を報告して終える。
5. notifications の各項目について、time の時刻に text の文面で通知を予約する。文面は書き換えない。
6. time が現在時刻の項目は、すぐに送る。

■ 質問されたとき
- 「今の脳機能は？」：最新の睡眠記録と now でページを開き、attention_now を答える。
- 「何時に寝るべき？」「あと1時間起きていたら？」：&whatif=HH:MM,HH:MM を付けて開き、bedtime_compare を答える。
- 「今カフェインを摂っていい？」：caffeine_cutoff と現在時刻を比べて答える。量が分かるときは &cafmg=<mg> を付ける。
- 「何時に勉強や作業をするのが良い？」：&win=HH:MM-HH:MM を付けて開き、focus_window を答える。

■ 補正
- 「谷の通知が早い」と言われたら、ずれの分数を正の値で &shift=<分> に入れる。「遅い」と言われたら負の値にする。以後のURLにも同じ値を付ける。

■ 守ること
- ページが返した数値と文面をそのまま使う。推測で補わない。
- ページが開けない、またはJSONが読めないときは、通知を予約しない。
- 結果は目安として伝える。診断や治療の助言にはしない。
- ページが返した件数を超えて通知しない。
```

## 仕様書に書かれていない部分の扱い

仕様書（コンディション予報ページ 仕様書）どおりに実装したうえで、定めのない部分は次のように決めています。

| 場面 | 扱い |
|---|---|
| 途中覚醒で分かれた区間が、どれも3時間未満 | 起床時刻の判定に限り、間隔60分以内の区間はひと続きの睡眠として数える（モデルの計算には、分かれたままの区間を使う） |
| 3時間以上の睡眠が直近24時間に無い | 直近24時間に終わった最後の睡眠区間の終わりを起床時刻にする。それも無ければエラー |
| 睡眠記録が7日分に足りない | エラー（睡眠負債と起床予定の中央値が計算できないため） |
| `now` より後に終わる睡眠区間がある | エラー（ブラウザの時計が現地時刻とずれている場合に、誤った値を出さないため） |
| 起床が活動時間帯の開始より遅い | ピーク・谷・日中平均は、活動時間帯のうち起床から就寝目標までの部分で集計する |
| 睡眠負債の「直近7日」 | 正午区切りで、当日の起床時刻を含む日までの7日 |
| ピーク・谷・集中に向く時間帯の刻み | 5分刻み（平均は1分刻みの値から計算） |
| `win` が `now` より前から始まる | `now` より前の区間は選ばない |
| `whatif` の時刻がすでに過ぎている | その時刻は比較に入れない |
| `whatif` が3件でない | night の文面は、件数に合わせて「〜なら〜%」を並べる |
| サンプル表示 | 固定のサンプル記録と固定の現在時刻（2026-11-10 07:10）で計算する。画面には通知の見本を出すが、結果ブロックの `notifications` は空 |
| 同じタブで `#` 以降だけが変わった | 計算し直して描き直す |

記録が1晩まるごと抜けていると、その夜は眠らなかったものとして計算されます（数値が大きく下がります）。

## テスト

```
node --test forecast/test/*.test.js
```

- `forecast.test.js`：計算部の単体テスト。`index.html` から計算部（`<script id="core">`）を取り出し、Node だけで実行します。仕様書8章の基準値をすべて含みます。
- `browser.test.js`：実際のブラウザでの確認（幅360pxで横スクロールなし、外部通信なし、ライト／ダーク、`#` の変更で再計算）。Playwright が無い環境では自動的に省略されます。

## 構成

```
forecast/
  index.html              成果物（これだけを公開すれば動く）
    <script id="core">    計算部。純粋関数だけ（DOM・Date・保存領域を使わない）
    <script id="ui">      画面部。計算結果を描画するだけ
  test/                   テスト
```
